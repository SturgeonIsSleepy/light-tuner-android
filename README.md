# 轻调 0.7.0

适配天玑 9400+（MT6991）、REDMI K80 Ultra、澎湃 OS3 与 KernelSU。包名：`io.github.sturgeonissleepy.lighttuner`。

## 使用与迁移

0.5.0／0.6.0 已使用新包名，可直接覆盖升级并保留配置及历史；以下步骤仅用于旧包名 `cc.ccwu.apptuner` 的迁移。

1. 在旧版结束接管并停止自动切换
2. 安装新版，在 KernelSU 授予新包名 Root 权限
3. 首次打开读取旧版的 v3 配置草稿，暂时保留旧应用
4. 检查配置、试用并确认，随后可卸载旧版，不再启动旧版调度

包名不同，不能覆盖安装或自动继承 Root 授权。两版共用历史 Root 接管目录以保留恢复记录，不应同时使用。

## 调度与恢复

支持 CPU 三簇和 GPU 范围、四类进程组 CPU0–7、三套预设和分应用配置。新增可选 sugov_ext 升降频响应及 top-app 利用率下限，包含在三预设、应用独立设置、小窗合并、试用、回滚与重启恢复中。响应参数默认跟随系统；「填入响应参考值」只填入未验证的可查看草稿，不自动启用。全局试用有 20 秒回滚，确认后保存。保留 sugov_ext、Power/MiPerf、温控和充电保护，不反复抢写被其他工具修改的值。

确认配置或启用自动切换后，KernelSU `/data/adb/service.d/85-lighttuner.sh` 恢复已确认配置。Root 守护每 5 秒检查监听和线程调度，失败时退避；守护自身退出由应用打开、开机广播或 Android 周期任务恢复。系统节电可能延迟周期任务，Root 撤销、安全模式或启动脚本禁用时不能承诺恢复。结束接管会停止恢复和线程调度。

小窗事件合并防抖，可见应用取配置并集，前台和顶层保留 CPU4–7。请求上限至少为 CPU0–3 1600 MHz、CPU4–6 2400 MHz、CPU7 3000 MHz、GPU 806 MHz，并匹配设备档位，实际频率仍受调速器与温控控制。小窗消失后保留 3 秒并复核一次，不持续轮询窗口。标准 freeform/pinned 状态无法识别的厂商迷你窗采用普通前台策略。

## 应用与性能记录

首页只保留接管状态、三套预设、全局默认、应用入口和设置。应用列表支持搜索、图标和配置摘要，进入应用详情后依次使用「性能记录」「线程策略」「历史记录」。返回键按上一级返回。日志、共享和后台恢复说明收进设置。分应用配置保存后自动写入后台，是否随前台切换由应用列表中的自动切换开关控制。

录制每秒采样一次，15–600 秒，退出界面后继续，结束即停止采样。在录制页面每 5 秒读取进度，离开或结束后停止界面刷新。录制自动尝试目标应用 FrameTimeline，缺失／过时后尝试 SurfaceFlinger 对应窗口呈现时间，不用显示刷新率冒充应用帧率。采集 CPU scaling_cur_freq 与 GED GPU 瞬时频率，缺失值留空，不使用上限替代。通过 UID 和进程名确定应用，多进程归到同一应用，无法确定宿主的隔离进程不猜测归属。最多 8192 个线程实例，线程增量时间线上限 200000 行；短暂线程可能遗漏。

点击线程查看平均／峰值占用、观察到的 CPU 时间、身份、核心掩码与 CPU 占用时间线。点击有效区间可查看附近 CPU/GPU 频率和最近运行核心。一个线程 100% 代表一个核心，平均值按整场统计时长计算，不按线程存活时长计算。最近运行核心不是核心驻留，瞬时频率不是精确频率暴露。中断记录的汇总可能停留在最后一个十秒检查点，界面采样时长与线程汇总时长可能不同。

候选建议由本地规则生成，不调用 AI 服务。至少 15 秒有效统计、10 次观测、平均占用 ≥30%，并排除按身份／名称识别的主线程、渲染、音频等关键线程；名称识别并不完备，仍需判断用途。天学网 `com.up366.mobile` 的具体 `Thread-N` 候选允许 CPU0–3，其他非关键高占用候选允许 CPU0–6，均不自动改写或推断为空转。建议匹配本次实际名称和版本，不自动生成覆盖所有 Thread-N 的规则。本版线程策略只设置核心掩码，没有线程 nice／uclamp／锁帧；新增的利用率下限属于顶层进程组配置。

线程策略修改、启用／停用、删除及下载策略合并统一先试用 20 秒，确认后才保存。Root 独立倒计时守护负责撤回，界面退出或被杀不会取消守护；守护异常时后台恢复会检查未确认记录并撤回。确认与撤回串行处理，旧令牌不能撤回新试用或已确认策略。未启用接管时只保存草稿，确认全局接管后可从线程页试用草稿。

规则匹配包名、安装版本和线程名，支持手动设置通配符，同名线程实例均匹配。核分配是允许核心而非关闭硬件核心，受 cpuset 约束。应用更新后旧规则不跨版本执行。空规则不启动扫描；有规则时每 3 秒只枚举配置应用的线程，保存 PID/TID/启动时间和原掩码，仅恢复仍为本项目写入值的线程。

本机保留最近 12 场完整／停止／中断的有效记录，历史可删除。导出 AI 分析 ZIP 包含 `summary.json`、`threads.tsv`、`frequency.csv`、`thread-timeline.csv`、`profile-before.json` 和中文 `README.txt`。不联网、不自动上传，包内包含包名、版本、进程名和 PID/TID，分享前可自行检查。新增 `frames.csv`、窗口统计、每秒帧数和 `metrics.csv`，包含可读取的目标窗口呈现时间、框架卡顿分类、帧时间线时长、电池电流／电压／温度与 GPU 利用率。FPS 按窗口去重，平均取首末有效呈现的活动区间，P95/P99 用有界直方图近似，饱和值不是精确长帧时长。latency 路径没有卡顿分类与帧时间线时长，相应值保持缺失。电池側功率为电流电压估算，充电或已识别外部供电样本不计入非充电平均；没有精确整机功率、SoC 温度或精确核心驻留，不将数据关联当作省电效果证明。格式与使用流程见[性能分析包说明](docs/performance-session.md)。

原生录制和线程规则均使用 arm64 工作进程。可选录制悬浮窗显示最近帧数、CPU/GPU 频率、电池侧读数，并提供停止／详情／隐藏按钮。需要用户在系统中允许悬浮窗，前台服务仅用于显示本次记录，结束／隐藏后退出；未开启浮窗时无 Android 常驻前台服务。Root 记录不依赖浮窗存活，不持有额外唤醒锁。界面采用莫奈明暗配色和平面短时动画，空闲不刷新；时间线按点击的线程在后台读取，历史及导出也在后台处理，不引入图表或分析 SDK。

## 构建

JDK 17+、Android SDK 36，运行 `.\gradlew.bat :app:assembleDebug --offline --console=plain`。原生 arm64 文件已附在 assets，改动 native/lightcore.c 后用 NDK 28.2.13676358 执行 `tools/build-native.ps1 -Sdk <SDK 路径>` 再构建。APK 使用现有调试签名。

本版仅编译打包，按用户要求未运行测试、未安装或操作手机。云端沿用已部署服务，本次没有重新部署或调用接口验证。后台恢复、GPU 节点、厂商小窗表现和真实耗电尚未实机验证；旧版本验证记录不能作为本版结论。源码包含应用、原生源码、Worker、数据库结构和构建工具，不包含日志、截图、缓存、管理员密钥或私有签名。
